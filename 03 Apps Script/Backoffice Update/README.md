## สิ่งที่แก้แล้ว

1. ALL BOOKS รวม Guide Books และ Magazine รวมหนังสือ/นิตยสารโมเดล กรองข้อมูลร่วมกัน และส่ง source+SKU ของเล่มที่เลือกจริง ไม่ใช้ตำแหน่งแถวเป็นรหัสประจำเล่ม; SKU ซ้ำในคลังเดียวกันถูกปฏิเสธการขาย
2. SALES เพิ่มประวัติชื่อ/รหัสเล่ม/คลัง/วิธีขาย/วันขาย/ราคาจริงจากสต็อก โดยแยกจากยอดรวมในสมุด SALES เดิม ข้อมูลเก่าที่ไม่มีวันขายแสดง “ไม่ทราบวันที่” ไม่สร้างวันที่หรือรายการรับเงินขึ้นมาเอง
3. Mark Sold และตะกร้าเลือกขายปกติ/ประมูล และราคาจริงต่อเล่มได้ วันที่ขายเลือกได้ทั้งรายการเดี่ยวและตะกร้า; ประมูลเขียน Status=Auction และ Sold Date โดยถือว่าเล่มนั้นขายแล้ว ป้องกันการขายซ้ำทั้ง Sold และ Auction
4. Add สำเร็จล้างชื่อ สำนักพิมพ์ สภาพ ต้นทุน ราคา และรายละเอียดเล่มทั้งหมด พร้อม reset auto-suggestion/keyboard selection; เมื่อ API แจ้งล้มเหลวข้อมูลยังอยู่ คลังที่เลือกและ Status=Instock เป็นค่าเริ่มต้นสำหรับเล่มใหม่
5. Quotation และ Price notify เรียงชื่อด้วยตัวเปรียบเทียบภาษาไทย/อังกฤษที่รู้จักเลข เช่น Final Fantasy 2 ก่อน Final Fantasy 10 โดยไม่สลับราคาข้ามเล่มหรือเปลี่ยนลำดับตะกร้าต้นฉบับ

## กติกาการบันทึกยอดขาย

- Price คือราคาสินค้าที่ขายจริง ไม่รวมค่าส่ง และไม่แปลงกลับด้วยสูตรค่าธรรมเนียม Shopee แบบเดิม
- ค่าขนส่งที่เรียกเก็บจากลูกค้าเริ่ม 50 + 10 บาทต่อเล่มถัดไป สูงสุด 100; ศูนย์เล่ม = 0 มีช่องแก้จำนวนจริงที่ตกลงกับลูกค้า
- `shipping` = ค่าใช้จ่ายที่ร้านจ่ายให้ผู้ขนส่ง ส่วน `customerShipping` = ที่เก็บลูกค้า บันทึกหนึ่งครั้งต่อคำสั่งซื้อ ไม่คูณต่อเล่ม
- SALES Shiping Cost เก็บค่าใช้จ่ายขนส่งจริงตามชื่อคอลัมน์เดิม; Note เก็บ customerShipping พร้อมรหัสคำขอบันทึก คลัง SKU วิธีขาย ช่องทาง และ `payment=UNRECORDED` หากชีตเดิมมี Product ID ก็เขียนให้ด้วย
- กำไรก่อนค่าธรรมเนียมของรายการใหม่ = ราคาสินค้า + ค่าส่งที่เก็บลูกค้า − Cost เดิม − ค่าใช้จ่ายขนส่ง ไม่บวกต้นทุนเดิมซ้ำ หากไม่มี Cost จะเว้นกำไรไว้ ค่าส่งที่ยังใส่ 0 ทำให้ยอดกำไรยังไม่ใช่ยอดสุดท้าย
- ยอด SALES เก่าคงตามที่เคยบันทึก ไม่คำนวณใหม่จากข้อสันนิษฐานเรื่องค่าส่ง รายงานนี้ยังไม่ใช่บัญชีรับเงิน และยังไม่หักค่าธรรมเนียมแพลตฟอร์ม

## การบันทึกค้างและการลองใหม่

การขายครั้งแรกจะสร้างแท็บ `OWA SALES REQUESTS` ในชีตที่ผูกกับสคริปต์ เก็บเจตนาบันทึกแต่ละคำสั่งซื้อใน JSON ต่อแถว สถานะ PENDING/DONE และ snapshot ราคา/ต้นทุน ไม่มีการเปลี่ยนคอลัมน์ inventory เดิม

ระบบตรวจทั้งตะกร้าก่อนเขียน ใช้ Script Lock และมี marker ใน SALES Note เพื่อค้นหารายการเดิมเมื่อเกิด timeout; จำกัด 1 checkout ค้างในเวลาเดียวกัน และ 50 เล่มต่อ checkout ขนาดข้อมูลต้องอยู่ในขอบเขตที่กำหนด ถ้าข้อผิดพลาดเกิดหลังเริ่มบันทึก ให้กด **Retry checkout** ในหน้า SALES เพื่อทำรายการเดิมต่อ ห้ามสร้างรายการใหม่หรือลบ journal/marker เพื่อแก้ปัญหา หาก browser storage หาย ระบบใช้รายการ PENDING จากชีตเพื่อทำต่อได้

นี่เป็นการบันทึกแบบทำต่อจากจุดค้างได้ ไม่ใช่ transaction แบบฐานข้อมูลที่ย้อนคืนทุกเซลล์อัตโนมัติ ระหว่าง PENDING ต้องหยุดแก้ stock/SALES/เรียงแถวด้วยมือ รวมถึงสคริปต์อื่นที่ไม่ใช้กลไกเดียวกัน จน Retry สำเร็จ หากมีคนแก้ SKU หรือลบแถวระหว่างนั้น ต้องตรวจ journal เทียบข้อมูลก่อนดำเนินการ

การแก้สถานะ Sold/Auction หรือย้อนกลับ Instock ผ่านฟอร์ม Edit ถูกปิด เพราะการคืนสินค้าต้องลงรายการปรับปรุงประวัติขายด้วย เครื่องมือเดาว่ารายการราคาต่ำคือ Auction ถูกปิดใน web app เนื่องจากไม่ใช่ข้อมูลการประมูลจริง; เมนูใน Code.gs เดิมยังไม่ได้แก้ ต้องตรวจจุดนี้ก่อนนำขึ้นร้าน
