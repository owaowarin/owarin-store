> สถานะ: **ออกแบบเท่านั้น — ยังไม่แตะโค้ด** · ขอบเขต: GAME GUIDE BOOKS (MAGAZINE ใช้สูตรเดิมไปก่อน)
> อ้างอิง: Code.gs v16 (`_buildSoldIndex`, `_calcGGBSoldPrice`, `CONDADJ`) + ข้อมูลจริงจาก OWARIN STORE.xlsx (1,295 แถว GGB, วิเคราะห์ 26 ก.ค. 2026)

## 0) สรุปผู้บริหาร

ระบบเดิมถามว่า **"เล่มนี้เคยขายเท่าไหร่"** — ระบบใหม่ถามว่า **"ราคาที่ถูกต้องของเล่มนี้ วันนี้ คือเท่าไหร่"**

ข้อมูลจริงชี้ปัญหา 3 ข้อที่ทำให้ "ขายถูกเกินไป" เป็นเรื่องเชิงโครงสร้าง ไม่ใช่ความบังเอิญ:

1. **Closed loop สมบูรณ์** — 77% ของการขาย (325/422) เกิดที่ราคา = Suggested เป๊ะ ๆ แปลว่าราคาที่ระบบแนะนำจะกลายเป็น comp ของตัวเองตลอดกาล ถ้าเคยแนะนำถูกไปหนึ่งครั้ง ราคานั้นจะถูกล็อกไว้ไม่มีวันขึ้น (median ไม่มีทางสูงกว่าค่าที่เคยขาย = **เพดานตายตัว** ทั้งที่ตลาด retro เป็นขาขึ้น)
2. **ระบบเดิมตั้งราคาได้แค่ 32% ของสต๊อก** — Instock 466 เล่ม มี comp ตรงเงื่อนไข (base+publisher+original) แค่ 147 เล่ม ที่เหลือ 68% เว้นว่างให้เดาเอง และใน comp ที่มี **76% เป็นจุดข้อมูลเดียว** (median ของเลขตัวเดียว)
3. **ไม่มีมิติเวลา** — เล่มที่หลุดใน 1 วัน กับเล่มที่ใช้เวลาขาย 18 เดือน ให้น้ำหนักเท่ากัน ทั้งที่ "ขายเร็วผิดปกติ" คือหลักฐานที่ชัดที่สุดว่าตั้งถูกไป

SP-2 แก้ด้วยกลไก 5 อย่าง: **(A)** แปลงทุก comp เป็นราคามาตรฐานสภาพ A ก่อนรวม (ใช้ข้อมูลบางให้คุ้มทุกแถว) · **(B)** ใช้ *ความเร็วที่ขายได้* ปรับแก้ราคาที่เคยขายถูกไป · **(C)** บันได fallback 6 ชั้น → coverage เพิ่มจาก 32% เป็น ~90% · **(D)** ของแพง/หายากบังคับผ่านมนุษย์ (Rare Guard) · **(E)** ราคาออกมาเป็น "ช่วง" ไม่ใช่เลขเดียว + กติกา "เปิดขอบบน ลดทีหลังได้ ขึ้นทีหลังไม่ได้"

Auction **ไม่เข้า logic ทุกกรณี** (เหมือนเดิม) — ข้อมูลยืนยันว่าถูกต้อง: ราคาจบ Auction เฉลี่ยแค่ **29%** ของราคา Sold ไตเติลเดียวกัน

## 2) จุดอ่อนเชิงโครงสร้างของ v14.3 (อ้างโค้ด)

1. **เพดานตายตัว + วงจรตอกย้ำราคาถูก** — `_calcGGBSoldPrice` ใช้ `_median` ของราคาที่เคยขาย → ค่าแนะนำไม่มีวันเกินอดีต และเมื่อ 77% ขายตาม suggestion ราคาถูกจะผลิตซ้ำตัวเองไม่รู้จบ
2. **ไม่ใช้เวลา** — `_buildSoldIndex` เก็บแค่ `{cond, price}` ทั้งที่ v16 มี `soldDate` แล้ว การขายเมื่อ 3 ปีก่อนกับเมื่อวานถ่วงน้ำหนักเท่ากัน และไม่มีข้อมูล "ขายเร็วแค่ไหน" เลย (ไม่มีวันที่ลงขาย)
3. **Match แคบเกิน** — key = base+publisher+original เป๊ะ → 68% ของสต๊อก NO-SOLD เว้นว่าง มนุษย์ตั้งเอง ไม่มีมาตรฐาน (ปัญหาที่ระบบเกิดมาเพื่อแก้)
4. **ปรับสภาพเป็นบาทคงที่** — `CONDADJ` (S+100/B−10/C−30/D−50): −50 บนเล่ม ฿100 คือ −50% แต่บนเล่ม ฿1,500 คือ −3% → บิดเบือนทั้งสองปลาย
5. **GGB ไม่มี cost floor** — ฝั่ง MAGAZINE มี `costFloor` แต่ `_calcGGBSoldPrice` ไม่แตะ Cost เลย → แนะนำต่ำกว่าทุนได้ (เกิดจริง 9 เคส)
6. **ไม่มีตัวแปรระดับเล่ม** — โปสเตอร์/แผนที่ครบ, ตราปั๊มร้านเช่า, เขียนชื่อ ไม่มีที่ให้บันทึก ทั้งที่โจทย์บอกเอง: ไม่มีเล่มไหนเหมือนกัน 100%
7. **ไม่มีทางออกสำหรับของหายาก** — เล่มที่ไม่เคยขายและหายาก (จุดที่เสียโอกาสแพงที่สุด) ระบบเว้นว่างเฉย ๆ แทนที่จะ flag ให้คนตัดสินใจพร้อมข้อมูลประกอบ
8. **ความกำกวมฐานราคา** — Market Place Price = (Price+50)×1.2 ถ้าการขายบางรายการบันทึกฐาน Shopee ปนฐานหน้าร้าน comp จะเพี้ยน ~20–30% โดยไม่รู้ตัว

## 3) ร้านชั้นนำทำอย่างไร → หยิบอะไรมา

| ร้าน/วงการ | แนวปฏิบัติ | สิ่งที่ SP-2 หยิบมา |
|---|---|---|
| Suruga-ya (ญี่ปุ่น, ของเกม retro) | ราคาไดนามิกตาม demand + ความเร็วขาย + สต๊อก | **Velocity feedback + ratchet** |
| BookOff | สูตรมาตรฐานกับของทั่วไป / ดึงของมีค่าออกมาตั้งราคาเอง (Premium shelf) | **สองชั้น: auto กับ commodity, มนุษย์กับ rare** |
| Mandarake / ร้านหนังสือหายาก | comps + ความครบ (obi/inserts) + ผู้เชี่ยวชาญเคาะ · "ถ้าเป็นเล่มเดียวในตลาด คุณคือคนกำหนดตลาด" | **Copy Flags + ราคาเป็นช่วง + เปิดขอบบน** |
| CeX / GameStop used | markup ขั้นต่ำจากราคารับซื้อเสมอ | **Cost floor** |

หลักร่วมของทุกเจ้า: ราคาไม่ใช่ "ค่าเฉลี่ยของอดีต" แต่คือ "การประเมินตลาดปัจจุบัน โดยใช้อดีตเป็นหลักฐาน" — และของหายากไม่ปล่อยให้สูตรตัดสิน

## 4) สถาปัตยกรรม SP-2

### 4.1 หลักคิดหลัก: แยก "ราคาไตเติล" ออกจาก "ราคาเล่ม"

```
TitleBase(A)  =  มูลค่าของไตเติลนี้ ที่สภาพ A มาตรฐาน   ← คำนวณจาก comp ทุกสภาพ
CopyPrice     =  TitleBase(A) × CondMult(เล่มนี้) × FlagAdj(เล่มนี้)
```

เดิม: กรองเฉพาะ comp สภาพตรงก่อน (ข้อมูลหด) — ใหม่: **ทุก comp ถูกแปลงเป็นเทียบเท่าสภาพ A ก่อนรวม** ทำให้ comp ทุกแถวมีประโยชน์เสมอ (สำคัญมากเมื่อ 76% ของ key มี comp เดียว) และตอบโจทย์ "ไม่มีเล่มไหนเหมือนกัน 100%": ระบบตีมูลค่า *ไตเติล* แล้วมนุษย์+flags ปรับเป็นมูลค่า *เล่มตรงหน้า*

### 4.2 Pipeline 6 ขั้น

**STEP 1 — หา comps ตามบันได fallback (พร้อมป้ายความมั่นใจ)**

| ชั้น | เงื่อนไข match | ป้าย | คาด coverage (จากข้อมูลจริง) |
|---|---|---|---|
| T1 | base title + publisher + original | `EXACT` | 32% |
| T2 | base title + publisher | `TITLE-PUB` | +3% |
| T3 | base title (ต่างสำนักพิมพ์ → ×ปัจจัยสำนักพิมพ์) | `TITLE` | +11% |
| T4 | ไม่มี comp → **Curve**: ตัวคูณราคาปกของ bucket **× ช่วงราคาปก** (v17.1) — publisher×platform×band → publisher×band → platform×band → band (ขั้นต่ำ n=8 ต่อ bucket) · **ไม่มีข้อมูลในช่วงปกนั้น = ไม่เดา** ตกไป T6 | `CURVE` | +50% |
| T5 | Market Ref (กรอกมือจากตลาดภายนอก เช่น Shopee sold / กลุ่ม FB / eBay) | `REF` | ตามที่กรอก |
| T6 | ไม่มีอะไรเลย → **คิว MANUAL** ไม่เว้นว่างเงียบ ๆ | `MANUAL` | ~10% (~48 เล่ม) |

**STEP 2 — ตีความ comp แต่ละตัว (หัวใจของการแก้ "ขายถูกไป")**

```
A_equiv = ราคาขายจริง ÷ CondMult(สภาพของ comp) × VelAdj(จำนวนวันที่ใช้ขาย)
```

| วันที่ใช้ขาย (Listed→Sold) | ความหมาย | VelAdj |
|---|---|---|
| ≤ 7 วัน | หลุดเร็วผิดปกติ = ราคานั้น *ต่ำกว่า* ตลาด | ×1.20 |
| 8–60 วัน | โซนสุขภาพดี | ×1.00 |
| 61–180 วัน | ช้า | ×0.95 |
| > 180 วัน | ราคานั้นคือเพดาน ไม่ใช่ราคาตลาด | ×0.90 |
| ไม่รู้วันลงขาย (ข้อมูลเก่า) | — | ×1.00 |

> นี่คือคำตอบตรง ๆ ของโจทย์ข้อ 2: เล่มที่ "ขายถูกเกินไป" ในอดีตเกือบทั้งหมดคือเล่มที่หลุดเร็ว ระบบใหม่ตีความราคานั้นเป็น **พื้น** ไม่ใช่ **ค่ากลาง**

**STEP 3 — รวมเป็น TitleBase(A)**

- Weighted median ของ A_equiv ถ่วงตามความใหม่: ขายภายใน 12 เดือน = 1.0 · 13–24 เดือน = 0.5 · เก่ากว่า = 0.25
- **Guard ขาขึ้น:** TitleBase ต้องไม่ต่ำกว่า A_equiv ของการขายครั้งล่าสุด (ตลาดขาขึ้น การขายล่าสุดคือหลักฐานที่สดที่สุด)

**STEP 4 — กลับเป็นราคาเล่มนี้**

| สภาพ | CondMult (default) | เทียบระบบเดิม |
|---|---|---|
| S | ×1.30 (ขั้นต่ำ +฿50) | เดิม +100 คงที่ |
| A | ×1.00 | อ้างอิง |
| B | ×0.85 | เดิม −10 (น้อยไปกับของแพง) |
| C | ×0.65 | เดิม −30 |
| D | ×0.45 | เดิม −50 |

Copy Flags (เลือกได้หลายอัน, ตัวอย่างชุดเริ่มต้น): โปสเตอร์/แผนที่ครบ **+10%** · ฉบับสีทั้งเล่ม **+15%** · ตราปั๊มร้านเช่า **−10%** · เขียนชื่อ/ขีดเขียน **−5%** · ปกซ่อม/เทป **−10%**

**STEP 5 — Guards**

- **Cost floor:** ราคา ≥ Cost × 1.5 — ถ้า floor ชนตลาด ระบบไม่ลดให้เอง แต่ติดป้าย `COST-FLOOR` ให้มนุษย์เลือก (ขายเท่าทุน+ / เข้าช่อง Auction ตามปรัชญาเดิม: Auction คือวาล์วระบายของ)
- **Monotonic guard:** ไม่แนะนำต่ำกว่าราคาขายล่าสุดของสภาพเดียวกัน/ดีกว่า
- ปัดเศษ ฿10 · ขั้นต่ำ ฿30 (คงเดิม)

**STEP 6 — Output เป็น "ช่วง + เหตุผล" ไม่ใช่เลขเดียว**

```
Target 280 · ช่วง 250–330 · เปิดขาย 320 (fast-sale signal)
[TITLE-PUB n=2 · comps: B@250/3d→353A, A@300/45d→300A · guard: ≥300]
```

- ช่วง = Target ×0.9 ถึง ×1.2 (ของ rare ขยายขอบบนเป็น ×1.3)
- **กติกาเปิดราคา: เปิดที่ขอบบนเสมอเมื่อมีสัญญาณ hot หรือ rare** — ลดราคาทีหลังทำได้ทุกเมื่อ แต่ขายถูกไปแล้วเอาคืนไม่ได้ นี่คือการกันเสียโอกาสแบบเดียวที่ irreversible
- ช่องเหตุผล = ต่อยอดคอลัมน์ `Max G Ref` เดิม ให้ตรวจสอบย้อนหลังได้ทุกตัวเลข

### 4.3 Velocity Ratchet — กลไกไล่หาเพดานตลาด (ของที่ระบบเดิมไม่มีเลย)

ไตเติลไหนขายหลุด ≤7 วัน **2 ครั้งติด** → เล่มถัดไป (RESTOCK) เสนอ **+20%** อัตโนมัติ และบวกต่อไปเรื่อย ๆ จนรอบขายกลับมาอยู่โซน 8–60 วัน → นี่คือ price discovery ขาขึ้นแบบ Suruga-ya: ให้ตลาดบอกเพดานเอง แทนที่จะล็อกไว้ที่ราคาประวัติศาสตร์ (มี cap +20%/ครั้ง และถอยอัตโนมัติถ้าเล่มค้างเกิน 60 วัน)

### 4.4 Rare Guard — ของแพงห้าม auto (หัวใจกันเสียโอกาส)

เข้าคิว `REVIEW` แทนการตั้งอัตโนมัติ เมื่อเข้าเงื่อนไขใดเงื่อนไขหนึ่ง:

- TitleBase (หรือ curve estimate) ≥ **฿400** (= p90 ของราคาขายจริง)
- ไม่มี comp และ Rarity = R1
- ขายครั้งล่าสุดเกิน 24 เดือน

ระบบแสดงข้อมูลครบ (curve, comp เก่า, cost, ช่อง Market Ref) แล้วให้มนุษย์เคาะ — ภาระงานจริงเล็กมาก: instock ราคา ≥฿400 มีแค่ **16 เล่ม** แต่เป็นกลุ่มที่เงินหายมากที่สุดถ้าตั้งพลาด (เคยขายถึง ฿3,200)

### 4.5 Auction

- **ไม่เป็น comp ทุกกรณี** (ตามข้อกำหนดข้อ 1 — ข้อมูลยืนยัน: 0.29× ของราคา Sold)
- ตัวเลือกเสริม (เปิด/ปิดได้): ใช้ราคาจบ Auction เป็น **หลักฐานพื้น** เท่านั้น — "ตลาดจ่ายอย่างน้อยเท่านี้แบบโล๊ะ" → sanity check ขาต่ำ ไม่มีผลดึงราคาลง

## 5) ตัวอย่างคำนวณ (เลขจริงตามพารามิเตอร์ข้างบน)

**A. เคสแก้ "ขายถูกไป"** — เล่มสภาพ B · ประวัติ: B ขาย ฿250 (หลุดใน 3 วัน), A ขาย ฿300 (45 วัน)
- เดิม: median B = **250** (= ราคาที่เพิ่งพิสูจน์ว่าถูกไปเพราะ 3 วันหลุด)
- ใหม่: B: 250×1.20 = 300 → ÷0.85 = 353 A-equiv · A: 300 → 300 A-equiv → TitleBase = 326
- เล่ม B: 326×0.85 = 277 → **Target 280 · ช่วง 250–330 · เปิด 330** (fast signal → ขอบบน) — ต่างจากเดิม +32%

**B. เคสไม่มี comp → Curve** — BRIGHT · PlayStation · ปก ฿85 · สภาพ A · cost ฿100
- เดิม: **เว้นว่าง**
- ใหม่: bucket BRIGHT (n=40, med 4.5×) → 85×4.5 = 383 → **Target 380 · ช่วง 340–460 · ป้าย CURVE(n=40)** · floor 150 ไม่ชน

**C. เคสหายาก → REVIEW** — GAMEMAG TOP SECRET · ปก ฿120 · สภาพ S · ไม่เคยขาย
- curve 5.8× → 696 ≈ 700 (ฐาน A) → เกิน ฿400 → **ไม่ auto** → ใบ REVIEW: "ฐาน A ≈ 700 · สภาพ S ×1.3 → Target 910 · ช่วง rare 820–1,180 · แนะนำเปิดขอบบน ~1,150 · กรอก Market Ref ถ้ามี · ห้ามต่ำกว่า 820 โดยไม่ยืนยัน"

**D. เคสชนทุน** — comp ให้ 80 แต่ cost 90 → floor 90×1.5 = 135 → **140 + ป้าย COST-FLOOR** ("ซื้อแพงไป หรือตลาดมี upside — คนตัดสิน") — เกิดจริงน้อย (9/363) แต่ต้องมีการ์ด

## 7) แผนทำจริง (ตามลำดับ ไม่ข้ามขั้น)

- **P0 — เริ่มได้พรุ่งนี้ ไม่ต้องเขียนโค้ด:** เพิ่ม 4 คอลัมน์ · เริ่มเก็บ Listed Date ทุกเล่มที่ลงใหม่ · ตกลงวินัยฐานราคา Sold
- **P1 — Engine หลัก (ยังไม่ใช้ velocity):** บันได T1–T6 + A-normalization + CondMult ใหม่ + floors + output ช่วง/เหตุผล + Rare Guard → แทน `_calcGGBSoldPrice` + `_buildSoldIndex` (จุดต่อโค้ดแคบ: `_recalcRow` ของ v16 เรียกใช้ต่อได้เลย ไม่กระทบ SKU/RESTOCK)
- **P1.5 — เก็บเกี่ยวทันที:** รัน engine ทับ Instock ทั้ง 466 เล่ม → รายการที่ราคาปัจจุบันต่ำกว่า Target เกิน 20% = **ของที่กำลังจะขายถูกไป แก้ก่อนหลุด** (คาดว่าเจอไม่น้อย เพราะราคาปัจจุบันมาจากระบบเพดานตายตัว)
- **P2 — เปิด velocity (หลังมี Listed Date สะสม 2–3 เดือน):** VelAdj + Ratchet
- **P3 — Calibration รายเดือน:** dashboard วันขายเฉลี่ยต่อช่วงราคา · % ขายหลุด ≤7 วัน (เป้า: ลดจาก ? → ~10%) · realized/suggested ratio · ปรับ CondMult/curve จากข้อมูลที่โตขึ้น

## 9) ความเสี่ยงที่รู้ตัวและวิธีกัน

- **ข้อมูลบาง:** ช่วงแรกของจำนวนมากอยู่ชั้น CURVE — ระบบจึงบอกป้ายความมั่นใจตรง ๆ ทุกครั้ง ดีกว่ามั่วเลขเดียวแบบมั่นใจ
- **Velocity เพี้ยนจาก exposure:** เล่มขายช้าอาจเพราะไม่เคยถูกโพสต์โปรโมท ไม่ใช่แพงไป → VelAdj ฝั่งลดถูกตั้งอ่อน (×0.90–0.95) โดยเจตนา ฝั่งขึ้น (×1.20) แรงกว่า เพราะ "หลุดเร็ว" โกหกยากกว่า "ขายช้า"
- **Ratchet overshoot:** มี cap และกลไกถอยอัตโนมัติ
- **ยังอ้างอิงข้อมูลตัวเองเป็นหลัก:** Market Ref คือช่องหายใจสู่ตลาดภายนอก — บังคับเฉพาะของ rare ที่เงินเดิมพันสูง
- **ภาระกรอกเพิ่ม:** ออกแบบให้ทุกช่องใหม่ optional ยกเว้น Listed Date ซึ่งอัตโนมัติ 100%

## 10) สิ่งที่ไม่เปลี่ยน

ไม่นับ Auction เป็น comp ✓ · ตัด RESTOCK ก่อน match ✓ · ปัดเศษ ฿10 ✓ · header-driven ✓ · โครง v16 (`_recalcRow`, LockService, Sold Date) รองรับได้ทั้งหมด — SP-2 เปลี่ยนเฉพาะไส้ pricing (`_buildSoldIndex` → comp engine ใหม่, `_calcGGBSoldPrice` → pipeline 6 ขั้น) ไม่แตะ SKU / RESTOCK / derived formulas / MAGAZINE
