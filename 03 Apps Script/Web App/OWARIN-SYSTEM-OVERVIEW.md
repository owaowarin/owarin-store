## 2) MAGAZINE → SP-2 (งานถัดไปทันที)

### สภาพปัจจุบัน

ใช้สูตร publisher-aware v13: ตั้งราคาจาก **ราคาปก** ล้วน ๆ + บวกลบตามสภาพเป็นบาทคงที่ (S+50/B−20/C−40) — **ไม่เคยดูราคาขายจริงเลย** ผลคือขายที่ราคา = suggested แค่ **18%** (GGB = 77%) แปลว่าคุณแก้ราคาด้วยมือเป็นปกติอยู่แล้ว = สูตรไม่ตรงความจริง

### ข้อมูลจริงบอกอะไร (555 แถว · Sold 252 · Instock 301)

| ประเด็น | ตัวเลข | ความหมาย |
|---|---|---|
| ราคาขาย | med ฿50 · p90 ฿150 · max ฿400 | ของถูกกว่า GGB มาก (med ฿260) |
| ตัวคูณ vs ราคาปก | ปก ≤25 = **4.0×** · 26–50 = **1.8×** · 51–100 = **0.6×** · 101–200 = **0.5×** · 201+ = **0.5×** | **ปกแพงขายได้ต่ำกว่าปกด้วยซ้ำ** — ยิ่งต้องแยก band |
| ตัวคูณตามสำนักพิมพ์ | ANIMATE 0.6× (n=186) · VIBULKIJ **3.3×** (n=39) · DEX 0.5× (n=18) | ต่างกัน 5 เท่า สูตรเดิมจับได้บ้างแต่หยาบ |
| ไตเติลขายซ้ำ ≥2 ครั้ง | แค่ 4 ไตเติล | เกือบทุกเล่มเป็น one-off → **comp ตรงตัวแทบไม่มี ต้องพึ่ง curve** |
| comp coverage | EXACT 78 · TITLE-PUB 1 · ไม่มี comp 222 (74%) | ตรงข้ามกับ GGB |

### แผน SP-2 for MAGAZINE (M-SP2)

**ใช้ engine เดียวกันเป๊ะ ไม่เขียนใหม่** — `_sp2CalcGGB` ไม่มีอะไรผูกกับ GGB เลย เปลี่ยนแค่ให้ `_calcSuggestedPrice` เรียกมันสำหรับ MAGAZINE ด้วย + ปรับพารามิเตอร์ 3 ตัวให้เข้ากับของถูก:

| พารามิเตอร์ | GGB | MAGAZINE | เหตุผล |
|---|---|---|---|
| ช่วงราคาปก (bands) | 50/100/200/400 | **25/50/100/200** | ราคาปกนิตยสารต่ำกว่า |
| เกณฑ์ REVIEW | ฿400 | **฿150** (= p90) | สเกลราคาต่างกัน 5 เท่า |
| CondMult | S 1.30 / A 1.00 / B 0.85 / C 0.65 / D 0.45 | เท่ากัน | สภาพเป็นสัดส่วน ไม่ผูกสเกล |

**ผลจำลองบน 301 เล่ม Instock:** EXACT 78 (26%) · CURVE 222 (74%) · **ตั้งราคาอัตโนมัติได้ 100%** โดยอิงราคาขายจริงเป็นครั้งแรก (curve ผ่านเกณฑ์ n≥8 ได้ 11 buckets)

**สิ่งที่ต้องทำ:** เพิ่ม 7 คอลัมน์เดียวกันในชีต MAGAZINE (`sp2Setup` รองรับอยู่แล้ว แค่ให้รับ sheetName) · `SP2` แตกเป็น `SP2.GGB` / `SP2.MAG` · `sp2Layout`/`sp2MigrateFlags`/`sp2Apply*` รับ sheetName · เว็บแอปเปิดปุ่ม SP-2 ให้ MAGAZINE

**ประเมิน:** แก้ Code.gs ~150 บรรทัด · WebApp/Index เล็กน้อย · **ครึ่งวัน**

## 3) ⚠️ Monthly Sales — เช็ค 1 จุดก่อนใช้ต่อ

เปลี่ยนชื่อชีตแล้ว **ระบบไม่พัง** เพราะ `_getSalesSheet()` หาชีตจาก *หัวคอลัมน์* ไม่ใช่ชื่อชีต (ต้องมี `Order` + `Product` + `Net Profit`) — ตราบใดที่ 3 หัวนี้ยังอยู่ ทุกอย่างทำงานปกติ

**แต่มีความเสี่ยงที่ต้องรู้:** ถ้าจะทำชีตรายเดือนหลายใบ (`Monthly Sales 2026-07`, `2026-08`, …) ระบบจะเจอใบแรกที่ match แล้วเขียนลงใบนั้นเสมอ — ผิดเดือนได้

**ทางแก้ที่แนะนำ (ทำตอนทำ M-SP2):** ตั้ง `SALES_SHEET = "Monthly Sales"` ตรง ๆ ใน config · หรือถ้าจะแยกรายเดือนจริง ให้ `_getSalesSheet()` เลือกจากชื่อที่ลงท้าย `YYYY-MM` ของเดือนปัจจุบัน แล้วสร้างใบใหม่อัตโนมัติเมื่อขึ้นเดือน

> ถ้ายังใช้ใบเดียวสะสมต่อ (แนะนำ — dashboard สรุปรายเดือนให้อยู่แล้ว) ไม่ต้องทำอะไรเลย

## 4) 🖼️ รูปราย listing — สเต็ปแรกที่ต้องการ

### ของที่มีอยู่แล้ว (สำรวจจริง)

| แหล่ง | จำนวน | โครงสร้าง | คุณภาพ |
|---|---:|---|---|
| **`GGB All/GGB - lists/<ชื่อเกม>/`** | **674 โฟลเดอร์ · 1,482 รูป** | โฟลเดอร์ต่อไตเติล · เฉลี่ย 2.2 รูป (สูงสุด 37) | ⭐ **ตัวจริง — ใช้อันนี้** |
| `Magazine/<หมวด>/<ชื่อ>.jpg` | 466 รูป | ไฟล์เดียวต่อเล่ม | ⭐ ใช้ได้ |
| `Products/Products/Books/…` | 710 รูป | ปะปน | ของเก่า |
| `Main Post New` · `SOLD OUT` · `New Arrival List` | 738 รูป | รูปโพสต์ FB | ไม่ใช่รูปสินค้า |

**อัตรา match ชื่อ (หลัง normalize ตัด RESTOCK/สัญลักษณ์):**
- GGB: ไตเติลทั้งหมด 692 → มีรูป **440 (64%)** · เฉพาะ **Instock 328 → มีรูป 188 (57%)**
- MAGAZINE: 451 → match ชื่อไฟล์ **301 (67%)**

### แผน 3 ระยะ

**M1 — เชื่อมรูปเข้าระบบ (ไม่ต้องมีเว็บไซต์ ใช้ในเว็บแอปก่อน)**

1. เพิ่มคอลัมน์ **`Images`** ในชีต (เก็บ path/ชื่อโฟลเดอร์ที่ match แล้ว) + **`Image Count`**
2. เขียน `sp2MatchImages()` — สแกนโฟลเดอร์รูป เทียบกับชื่อไตเติลด้วย normalize เดียวกับที่ทดสอบแล้ว → เติมอัตโนมัติ **~440 ไตเติล GGB + ~300 MAGAZINE** พร้อมรายงานว่าเล่มไหนยังไม่มีรูป
3. เว็บแอปโชว์ thumbnail ในการ์ดสินค้า + gallery ตอนกดเปิด
4. ได้ **รายการถ่ายรูปเพิ่ม** ทันที: Instock 140 ไตเติลที่ยังไม่มีรูป (คือของที่ขายไม่ได้เพราะลูกค้าไม่เห็นของ)

> ปัญหาเทคนิคที่ต้องตัดสินใจ: รูปอยู่บน OneDrive ในเครื่อง เว็บแอป (Apps Script) เห็นไม่ได้ → ต้อง **อัปโหลดขึ้น Google Drive** โฟลเดอร์เดียว แล้วเก็บ `fileId` ในชีต (`https://drive.google.com/thumbnail?id=…` ใช้เป็น `<img src>` ได้เลย) · 1.9 GB ทั้งหมด แต่ถ้าอัปเฉพาะ Instock + ย่อขนาด ~200–300 MB

**M2 — ยกระดับเป็นคลังรูปจริง**
- ตั้งชื่อไฟล์เป็น **SKU** (`OWA-GGBB011YKBR02-1.jpg`) → ผูกกับ *เล่ม* ไม่ใช่ *ไตเติล* (สำคัญ เพราะ RESTOCK แต่ละเล่มสภาพไม่เท่ากัน — ตรงกับหลักการ SP-2 ที่ว่าไม่มีเล่มไหนเหมือนกัน 100%)
- รูปแรก = ปก (thumbnail) · รูปถัดไป = สภาพ/ตำหนิ/ของแถม
- ย่อ + ใส่ลายน้ำอัตโนมัติ (มี `owarin_watermark_studio.html` อยู่แล้ว — ต่อยอดเป็น batch)

**M3 — เว็บไซต์**
- Apps Script `doGet` เพิ่ม endpoint `?api=catalog` คืน JSON เฉพาะ **Instock + มีรูป + ราคาพร้อมขาย** (กรอง REVIEW ออก ไม่ให้ของที่ยังไม่เคาะราคาหลุดขึ้นเว็บ)
- หน้าเว็บ = static site (Cloudflare Pages / Vercel) ดึง JSON มา render · รูปเสิร์ฟจาก Drive หรือ Cloudflare Images
- ฟีเจอร์: ค้นหา/กรองตามเครื่อง-สำนักพิมพ์-ราคา · หน้ารายตัวพร้อมแกลเลอรี · ปุ่มทัก LINE/FB พร้อม SKU · ป้าย "เล่มเดียวในร้าน"
- **ชีตยังเป็นแหล่งความจริงเดียว** — ขายแล้วกด Mark Sold ในเว็บแอป เว็บไซต์อัปเดตตามรอบ cache
